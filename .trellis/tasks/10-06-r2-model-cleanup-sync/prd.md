# 清洗并按模型同步 Cloudflare R2 数据

## Goal

对 Cloudflare R2 源桶 `zhao2` 中的归档对象进行只读模型识别，生成完整的模型与源对象报告；待用户提供目标桶名称后，再将命中模型的整个源对象按模型复制到对应目标桶。

## What I already know

* R2 使用 S3 兼容 endpoint；本地已配置名为 `zhao2` 的 `rclone` remote。
* 源桶名称为 `zhao2`，账户级列桶权限不可用，但已知桶可直接访问。
* 初步探查得到约 1,407 个对象、约 14.5 GB。
* 源对象主要是 `.tar.gz`，压缩包内部路径类似 `roots/primary/<model-name>/...`。
* 模型应从压缩包内部路径识别，不解析 body、JSONL 或请求正文。
* 第一阶段扫描全部源对象，不能写入、删除或覆盖 R2 数据。

## Requirements (evolving)

* 按 object key 字典序处理对象；抽样探查曾约定前 100 个及固定种子 `20261006` 从前 1,000 个抽取 100 个，但正式报告扫描全部对象。
* 识别压缩包内 `roots/primary/<模型名>/` 路径，并统计每个模型命中的源对象。
* 一个源对象包含多个模型时，报告中归入每个命中的模型；后续同步时复制到每个模型对应的目标桶。
* 第一阶段仅生成 JSON 报告，包含模型汇总、每个模型的完整源 object key、对象大小与模型总大小、未识别/非 tar.gz/损坏/超时对象。
* 第二阶段目标桶名称由用户后续提供；在此之前不得执行复制。
* endpoint、访问密钥 ID 和机密访问密钥由管理员后续在服务器端设置界面输入，不写死在代码中。
* 源桶名称也由管理员在连接设置页面输入，不固定为 `zhao2`。
* 目标对象保留源 object key，复制整个 `.tar.gz` 对象，不拆分压缩包内容。
* 目标桶不存在、模型没有目标桶配置或对象无法读取时，必须报告并跳过，不自动创建桶。
* 凭据只能通过本地 `rclone` 配置或环境变量读取，不得写入代码、任务文件、报告、命令参数或日志。
* 第一版加入单对象超时和有限重试；单个对象失败后记录并继续处理其他对象。
* 单对象读取/扫描超时为 120 秒；网络错误最多重试 2 次；压缩包损坏不重试并记录；单对象失败后继续处理其他对象。
* 交付形式改为可部署到服务器的 Web 界面，而不是仅提供命令行。
* Web 界面必须先通过外部密码认证才能访问；密码不得硬编码或写入仓库。
* 界面需要明确区分只读模型报告与实际同步操作，避免打开页面就触发写入。
* 第一版采用单管理员密码和服务端会话 Cookie；密码通过服务器环境变量注入。
* 同步界面按模型展示对象数量和总大小，允许勾选模型并在二次确认后启动。
* 每个模型可配置一个目标桶，并提供只读“测试连接”操作；测试成功后仍需单独确认并点击开始同步。
* 连接设置页面只对已认证管理员开放；凭据不得回显、写入 JSON 报告或发送到浏览器端脚本。
* Web 界面输入的 R2 连接参数只保存在服务器进程内存，服务重启后要求重新输入，不持久化到磁盘。
* 同步遇到已有目标 object key 时，内容一致则跳过；内容不一致则报告冲突并默认跳过，不自动覆盖。
* 第一版使用一组连接信息同时访问源桶和所有目标桶；暂不支持按目标桶配置不同账户。
* 源桶和目标桶可为同一 R2 账户下的不同桶；同一组连接是否具备每个目标桶权限由连接测试和实际同步验证，不因同账户而默认放行。
* 连接测试只执行非写入验证：endpoint/凭据有效、源桶可读取、目标桶存在且可读取；不通过临时对象验证写权限。
* 实际写权限在开始同步时由服务端 `CopyObject` 验证；目标桶不存在或权限不足时记录并跳过，不创建临时对象。
* 首选 Docker Compose 部署；管理员密码通过环境变量注入，R2 凭据仍只在服务进程内存中使用。
* 第一版对象同步采用 R2 服务端 `CopyObject`；应用不下载或转发完整归档，目标 key 与源 key 完全一致。
* 完整扫描在服务器后台任务中运行，界面展示进度；同一时间只允许一个扫描任务，结束后生成 JSON 报告。
* 第一版本地开发可使用 HTTP；生产环境在配置 HTTPS 前不得通过公网传输密码或 R2 凭据。
* 实际同步也在服务器后台任务中运行，页面展示进度；同一时间只允许一个同步任务，页面关闭后任务继续。
* JSON 扫描报告和同步结果保存到服务器受控数据目录，通过 Docker volume 持久化；仅认证用户可查看或下载。
* 模型到目标桶的映射持久化到服务器/Docker volume，仅保存模型名和桶名，不保存 endpoint 或任何密钥。
* Web 技术采用 FastAPI 后端 + React 前端；React 负责界面交互，FastAPI 负责认证、R2 操作和后台任务。
* React 生产构建后由 FastAPI 提供静态文件，采用单应用容器部署，减少跨域和反向代理复杂度。
* MVP 只覆盖：登录、连接设置、只读扫描、模型报告、目标桶配置、测试连接、模型选择、二次确认、后台同步和结果查看。

## Acceptance Criteria (evolving)

* [ ] 可只读列出并扫描源桶全部对象，不执行上传、删除或覆盖。
* [ ] 能从归档目录路径提取模型名，并统计模型命中对象数及大小。
* [ ] JSON 报告包含成功识别、未识别、非归档、读取失败和超时对象信息。
* [ ] 同一对象命中多个模型时，报告能保留多模型关联且不重复计算源对象本身。
* [ ] 第二阶段仅向已配置且已存在的目标桶复制，保留 object key，并具备可重试/幂等行为。
* [ ] 凭据不会出现在源码、版本控制、任务产物或普通运行日志中。
* [ ] 未认证用户不能查看桶数据、模型报告或触发同步。
* [ ] 服务器部署时可通过环境变量或外部密钥配置认证密码和 R2 凭据。
* [ ] 登录会话使用 HttpOnly、Secure、SameSite Cookie，未认证请求不能访问报告或同步接口。
* [ ] 测试连接不会创建、上传、删除或覆盖对象；实际同步只能由独立的明确操作触发。
* [ ] 连接测试对源桶和目标桶只执行只读检查，不将“可读取”误报为“已验证可写”。
* [ ] 重复同步不会覆盖一致对象；不一致对象会作为冲突报告，除非管理员明确选择覆盖。
* [ ] 长时间扫描不会依赖浏览器长连接，页面可离开后重新查看任务状态和报告。
* [ ] 长时间同步不会依赖浏览器长连接，页面可离开后重新查看同步状态和结果。
* [ ] 报告和任务结果在服务重启后仍可从受控数据目录恢复，且不包含任何凭据。
* [ ] 服务重启后模型目标桶映射仍可用，但 R2 连接参数必须重新输入。
* [ ] React 前端和 FastAPI 后端可在 Docker Compose 部署中稳定启动，并通过认证后的 API 完成完整流程。
* [ ] 生产构建后的单应用容器可同时提供 React 页面和 FastAPI API。

## Open Questions

* 第二阶段目标桶映射清单及命名由用户在界面中提供。
* 部署方式、域名/HTTPS、反向代理和端口尚未确定。
* 未来是否支持源桶和目标桶使用不同凭据，不纳入第一版。
* Docker Compose 中的 HTTPS 终止和反向代理组件尚未确定。
* 任务历史保留时长和自动清理策略尚未确定。
* 登录失败延迟、按 IP 锁定等应用内防护暂不纳入第一版，生产环境应由 HTTPS/反向代理补充。

## Out of Scope

* 不修改源桶对象。
* 不自动创建目标桶。
* 不拆分或重打包 `.tar.gz`，不清洗归档内部记录。
* 不自动猜测未提供的目标桶映射。
* 不在项目中保存任何访问密钥。
* 第一版不包含多用户、角色权限、注册、找回密码或公开访问功能，除非后续明确加入。
* 不包含定时同步、增量监控、删除目标对象、任务取消或断点续跑。

## Technical Notes

* 当前仓库尚无业务代码，只有 Trellis 工作流文件；实现需要先建立清晰的 CLI/配置边界。
* 只读探查过程中发现账户级 `ListBuckets` 返回 403，但已知桶 `zhao2` 可访问。
* 曾有串行归档扫描因个别对象读取较慢而停止；正式实现需要单对象超时、隔离失败和可恢复进度。
