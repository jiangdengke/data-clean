# 简化工作区并说明模型分类能力边界

## Goal

移除工作区中抽象且用户不需要的标题和技术路径展示，明确连接配置后如何扫描，并核对现有扫描与同步流程是否支持持续分类和清洗需求。

## What I already know

- 当前页面显示“数据工作区 / 源桶工作区”及说明“按源桶查看模型，为每个模型设置目标桶，然后执行同步”。用户要求去掉这些内容。
- 扫描卡片向用户展示 `roots/primary/<model>/`，但当前后端用它从 `.tar.gz` 归档内部成员路径识别模型名。
- 扫描只读列举配置的源桶并逐个检查对象；模型识别目前仅针对 `.tar.gz`，不会修改归档内容。
- 扫描完成后需配置模型到目标桶映射，保存映射并预检目标桶，再由管理员显式启动 CopyObject 同步。
- 当前无自动周期扫描、对象入桶触发、增量监控或归档内部数据清洗功能。
- 同一归档命中多个模型时，当前同步会把完整源归档复制到每个关联模型的目标桶，不会从归档中拆分模型数据。

## Requirements

- 移除 Dashboard 顶部的“数据工作区”“源桶工作区”和相应宣传式副标题。
- 从扫描卡片移除 `roots/primary/<model>/` 技术路径展示，不改变后端既有识别规则。
- 用简明中文说明：保存连接后可测试连接，再点击“开始扫描”；扫描读取归档目录来判断模型，不修改源对象。
- 保留连接、扫描、映射、目标桶检查、同步功能及安全边界。
- 不在本次改动中实现自动持续扫描、对象拆分或内容清洗；清楚评估并报告现有差距。

## Acceptance Criteria

- [ ] 指定的抽象标题和技术路径不再显示在已登录工作区。
- [ ] 配置后扫描的操作顺序在界面中清楚易懂。
- [ ] 归档模型识别及同步后端行为没有改变。
- [ ] 前端 lint 与 production build 通过。
- [ ] 向用户说明当前功能对“源桶数据按模型分流”及“持续筛选/清洗”的符合程度。

## Definition of Done

- 前端 lint/build 通过，差异检查通过。
- 给出配置后启动扫描步骤和当前能力边界。

## Out of Scope

- 自动定时、事件触发或增量扫描。
- `.tar.gz` 内部数据拆分、重打包、内容清洗或数据转换。
- 修改现有后端扫描、同步或 R2 操作行为。

## Technical Notes

- 前端：`frontend/src/main.tsx`。
- 识别规则：`backend/scanner.py` 中 `MODEL_MEMBER_PATTERN`。
- 同步展开：`backend/sync.py` 中 `create_sync_actions`。
- 前端规范：`.trellis/spec/frontend/index.md`、`components.md`、`css-layout.md`、`quality.md`。
